# 과제 02: 길이 기반 메시지 프레이밍

## 선수 조건

- 과제 01의 완료 조건을 모두 검증했다.
- TCP가 바이트 스트림이라는 점을 설명할 수 있다.

## 학습 목표

- TCP stream과 애플리케이션 메시지의 차이를 이해한다.
- 부분 읽기와 부분 쓰기를 처리한다.
- 신뢰할 수 없는 길이 값을 안전하게 검증한다.

## 이번 과제에서 익힐 Rust

- 로직을 작은 함수로 나누고 매개변수와 반환 타입을 직접 적는 방법
- `u32`, `usize`처럼 용도가 다른 정수 타입과 안전한 변환
- `[u8; 4]`, `Vec<u8>`와 byte slice를 상황에 맞게 선택하는 방법
- 정수를 byte 배열로 바꾸고 다시 복원하는 메서드
- `Result`를 반환하는 반복 작업에서 정상 EOF와 잘린 입력을 구분하는 방법

## 검색 키워드

- 언어: `Rust function parameters return type`, `Rust Vec u8`, `Rust usize u32 conversion`, `Rust match Result`
- byte 변환: `Rust u32 to_be_bytes from_be_bytes`, `Rust network byte order big endian`
- 정확한 읽기: `Rust Read read_exact`, `Rust read loop exact number bytes`, `Rust read_exact UnexpectedEof bytes unspecified`
- 안전성: `Rust checked integer conversion TryFrom`, `Rust allocate Vec untrusted length`

## 문제

TCP는 애플리케이션 메시지 경계를 보존하지 않는다. 각 메시지 앞에 고정 크기의 길이 정보를 붙이는 규칙을 정의하고, 메시지를 정확히 하나씩 복원해 돌려주는 echo 프로토콜을 만든다.

## 제한 조건

- 과제 01의 서버를 기반으로 한다.
- 길이 필드의 크기와 byte order를 문서로 정의한다.
- 메시지 최대 크기를 명시한다.
- 길이 정보와 본문이 여러 번의 읽기로 나뉘어 도착하는 경우를 처리한다.
- 여러 메시지가 한 번에 도착하는 경우를 처리한다.
- 잘못된 길이 때문에 무제한 메모리를 할당하지 않는다.

## 구현 순서

1. wire format을 코드보다 먼저 글로 정의한다.
2. 길이 필드만 정확히 읽는다.
3. 길이를 검증하고 허용 범위를 벗어난 입력의 정책을 정한다.
4. 선언된 길이만큼 본문을 모은다.
5. 완성된 메시지만 echo한다.
6. 한 연결에서 다음 메시지를 계속 처리한다.

## 단계별 힌트

1. 먼저 길이 필드를 몇 byte로 표현할지 정한다. 예를 들어 고정 크기 정수를 선택했다면 대응하는 고정 크기 배열이 필요하다.
2. 정수의 `to_be_bytes`와 `from_be_bytes` 문서를 읽고 송신자와 수신자가 같은 byte order를 쓰게 한다.
3. 새 frame을 시작하기 전에 첫 `read`가 `0`이면 정상적인 연결 종료로 볼 수 있다. 한 byte라도 받은 뒤에는 직접 진행량을 세며 header가 찰 때까지 반복하고, 그 도중 `0`이 나오면 잘린 header로 구분한다.
4. 네트워크에서 얻은 길이를 검증하기 전에 그 크기의 `Vec`을 만들지 않는다. 먼저 최대 크기와 정수 변환 가능 여부를 확인한다.
5. header를 읽은 뒤 본문 길이가 `0`인 경우도 유효한 메시지인지 정책을 정한다.
6. 메시지 하나를 처리하는 함수와 연결에서 여러 메시지를 반복하는 함수를 분리하면 EOF의 의미를 구분하기 쉽다.
7. `read_exact`는 실패했을 때 몇 byte를 읽었는지와 buffer 내용을 보장하지 않는다. 정상 EOF와 부분 frame을 구분해야 하는 경계에서는 이 메서드 하나에만 의존하지 않는다.

## 완료 조건

- 빈 메시지, 짧은 메시지와 버퍼보다 큰 메시지의 정책이 명확하다.
- 한 연결에서 여러 메시지를 순서대로 주고받을 수 있다.
- 길이 정보 또는 본문 중간에 연결이 종료될 때 무한 대기하거나 잘못된 메시지를 만들지 않는다.
- 최대 크기를 넘는 메시지를 정의한 방식으로 거부한다.
- 메시지가 여러 읽기로 분할되거나 한 읽기에 합쳐져도 결과가 같다.
- 길이 header를 0, 1, 2, 3 byte까지만 보낸 뒤 종료하는 경우와 본문 중간에 종료하는 경우가 각각 정의한 결과가 된다.

- 부분 읽기와 부분 쓰기는 각각 어떻게 처리해야 하는가?
- 공격자가 매우 큰 길이를 보냈을 때 어떤 문제가 생길 수 있는가?

- `read_exact`가 `UnexpectedEof`를 반환했을 때 실제 진행량을 알 수 있는가?
