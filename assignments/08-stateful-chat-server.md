# 과제 08: 상태 기반 채팅 서버

## 선수 조건

- 다중 TCP 연결을 동시에 처리할 수 있다.
- TCP framing과 연결 종료를 안정적으로 다룬다.
- HTTP의 요청 상태와 TCP 연결 상태를 구분할 수 있다.

## 학습 목표

- 연결을 유지하는 상태 기반 애플리케이션 프로토콜을 설계한다.
- 여러 연결이 공유하는 사용자 상태를 안전하게 관리한다.
- 느린 소비자와 비정상 종료의 영향을 제한한다.

## 문제

TCP 연결을 유지하며 여러 사용자가 이름을 등록하고 메시지를 주고받는 간단한 채팅 프로토콜을 설계한다. 서버는 현재 연결된 사용자를 기억한다.

## 제한 조건

- 메시지 framing 규칙을 먼저 문서로 정의한다.
- 중복 사용자 이름에 대한 정책을 정한다.
- 공유 상태 접근을 동기화한다.
- 느리거나 종료된 클라이언트 하나가 전체 채팅을 멈추지 않게 한다.
- HTTP 구현과 채팅 구현의 상태 관리 차이를 기록한다.
- lock을 획득하는 범위와 네트워크 I/O의 관계를 의식적으로 설계한다.

## 구현 순서

1. 명령과 서버 이벤트의 wire format을 정의한다.
2. 이름 등록과 중복 검증을 구현한다.
3. 연결된 사용자 목록의 소유자를 정한다.
4. 메시지를 다른 사용자에게 전달한다.
5. 정상 종료와 비정상 종료에서 사용자 상태를 제거한다.
6. 느린 클라이언트가 있을 때의 정책을 실험한다.

## 완료 조건

- 둘 이상의 사용자가 동시에 접속하고 메시지를 교환한다.
- 입장, 메시지와 퇴장 이벤트가 정의한 순서로 전달된다.
- 클라이언트 비정상 종료 후 사용자 상태가 정리된다.
- 중복 이름이 정의한 방식으로 처리된다.
- 공유 상태에서 가능한 경쟁 조건을 하나 이상 설명한다.

## 직접 조사할 질문

- 연결 상태와 사용자 세션 상태는 같은 것인가?
- 여러 스레드가 같은 사용자 목록을 수정하면 어떤 문제가 생기는가?
- lock을 잡은 상태로 네트워크 쓰기를 수행하면 어떤 위험이 있는가?
- 느린 소비자에게 어떤 정책을 적용할 수 있는가?
- broadcast 도중 연결이 종료되면 어떤 상태를 정리해야 하는가?
