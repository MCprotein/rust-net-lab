# 과제 01: 단일 클라이언트 TCP Echo Server

## 선수 조건

- `cargo run`으로 현재 프로젝트를 실행할 수 있다.
- 변수, 반복문, `Result`와 `?`의 기본 의미를 알고 있다.

## 학습 목표

- TCP listener와 연결된 stream의 역할을 구분한다.
- 바이트 읽기, 쓰기와 연결 종료를 직접 처리한다.
- 컴파일 오류와 입출력 오류를 구분한다.

## 문제

`127.0.0.1:7878`에서 연결을 기다리고, 클라이언트가 보낸 바이트를 그대로 돌려주는 서버를 만든다. 한 클라이언트가 연결을 종료하면 다음 클라이언트를 받을 수 있어야 한다.

## 제한 조건

- Rust 표준 라이브러리만 사용한다.
- 비동기 런타임과 외부 crate를 사용하지 않는다.
- 입력이 UTF-8이라고 가정하지 않는다.
- 우선 한 번에 한 클라이언트만 처리한다.
- 완성된 echo server 예제를 복사하지 않는다.

## 구현 순서

1. 서버가 지정된 주소에서 연결을 기다리게 한다.
2. 클라이언트 하나의 연결을 수락한다.
3. 연결에서 읽은 바이트 수를 관찰한다.
4. 실제로 읽은 바이트만 클라이언트에 돌려준다.
5. 클라이언트 종료를 감지한다.
6. 다음 클라이언트를 받을 수 있게 연결 수락을 반복한다.

## 완료 조건

- 다른 터미널에서 `nc 127.0.0.1 7878`로 연결할 수 있다.
- 입력한 데이터가 변형되지 않고 돌아온다.
- 한 클라이언트가 종료된 후 새로운 클라이언트가 연결할 수 있다.
- 클라이언트 종료 후 서버가 빈 반복문을 돌며 CPU를 계속 사용하지 않는다.
- 읽기 또는 쓰기 실패가 조용히 무시되지 않는다.

## 직접 조사할 질문

- TCP에서 listener와 연결된 stream은 어떤 역할 차이가 있는가?
- 읽기 함수가 반환하는 숫자는 무엇을 의미하는가?
- 읽기 결과가 `0`이면 연결에는 어떤 일이 일어난 것인가?
- 버퍼 전체가 아니라 실제로 읽은 바이트만 보내야 하는 이유는 무엇인가?
- 한 번의 쓰기 호출이 항상 전체 데이터를 전송하는가?
