# 과제 03: 여러 TCP 클라이언트 동시 처리

## 선수 조건

- 과제 02의 framing된 echo가 한 연결에서 안정적으로 동작한다.
- 연결별 상태와 listener 상태를 구분할 수 있다.

## 학습 목표

- thread-per-connection 실행 모델을 경험한다.
- Rust의 소유권이 스레드 경계에서 어떻게 작동하는지 확인한다.
- 연결별 오류와 서버 전체 오류를 분리한다.

## 문제

한 클라이언트가 연결을 유지하거나 천천히 데이터를 보내더라도 다른 클라이언트가 독립적으로 echo 서비스를 사용할 수 있게 만든다.

## 제한 조건

- 처음에는 클라이언트 연결마다 OS 스레드 하나를 사용한다.
- 프로토콜 규칙과 연결 수락 책임을 분리한다.
- 클라이언트 하나의 실패가 listener 전체를 종료시키지 않게 한다.
- 무제한 연결과 무제한 스레드가 만드는 위험을 문서화한다.
- 아직 thread pool이나 비동기 런타임은 구현하지 않는다.

## 구현 순서

1. 현재 코드에서 listener가 책임지는 부분과 연결이 책임지는 부분을 표시한다.
2. 연결 하나의 처리 흐름을 독립된 실행 단위로 옮긴다.
3. 연결 처리에 필요한 값의 소유권을 스레드로 이동한다.
4. 연결별 성공과 실패를 관찰할 방법을 만든다.
5. 느린 클라이언트와 정상 클라이언트를 동시에 실행해 본다.

## 완료 조건

- 두 개 이상의 클라이언트를 동시에 연결할 수 있다.
- 한 클라이언트가 입력 없이 대기해도 다른 클라이언트는 응답을 받는다.
- 한 클라이언트가 비정상 종료돼도 새로운 연결을 받을 수 있다.
- 연결별 오류와 서버 전체 오류를 구분해 설명할 수 있다.
- 종료된 연결의 자원이 계속 남지 않는다.

## 직접 조사할 질문

- 스레드로 이동되는 값에는 어떤 소유권 조건이 필요한가?
- listener, 연결 처리기와 프로토콜 로직은 각각 어떤 오류를 책임져야 하는가?
- thread-per-connection 방식의 장점과 한계는 무엇인가?
- 스레드를 생성하지 못했을 때 서버는 어떤 정책을 선택할 수 있는가?
