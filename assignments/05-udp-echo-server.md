# 과제 05: UDP Echo Server

## 선수 조건

- TCP stream의 연결과 메시지 framing을 설명할 수 있다.
- 과제 04에서 프로토콜과 전송 책임을 분리했다.

## 학습 목표

- UDP 데이터그램의 메시지 경계를 이해한다.
- 연결 없이 송신자 주소를 기준으로 응답한다.
- TCP와 UDP의 상태 및 실패 의미를 비교한다.

## 문제

UDP로 받은 하나의 데이터그램을 보낸 주소로 그대로 돌려주는 서버를 만든다. TCP 구현과 비교해 연결, 순서와 메시지 경계의 차이를 기록한다.

## 제한 조건

- Rust 표준 라이브러리만 사용한다.
- TCP용 스트림 추상화에 UDP를 억지로 끼워 넣지 않는다.
- 송신자의 주소를 데이터그램과 함께 처리한다.
- 수신 버퍼보다 큰 데이터그램에 대한 정책을 확인한다.
- 신뢰성, 순서 보장이나 재전송을 임의로 추가하지 않는다.

## 구현 순서

1. TCP echo에서 연결별로 존재하던 상태를 나열한다.
2. UDP socket을 주소에 연결하고 데이터그램을 기다린다.
3. 수신 데이터와 송신자 주소를 함께 확인한다.
4. 같은 payload를 정확한 송신자에게 보낸다.
5. 여러 송신자의 데이터그램을 번갈아 보내 검증한다.

## 완료 조건

- 여러 송신자가 별도의 연결 생성 없이 데이터그램을 보낼 수 있다.
- 각 응답이 올바른 송신자에게 돌아간다.
- 빈 데이터그램의 의미와 처리 방식을 설명할 수 있다.
- TCP echo와 UDP echo의 상태 및 실패 차이를 비교해 기록한다.
- 수신 버퍼를 넘는 데이터그램에 대한 관찰 결과 또는 정책이 기록되어 있다.

## 직접 조사할 질문

- UDP는 어떤 메시지 경계를 보존하는가?
- UDP에서 연결이 없다는 말과 connected UDP socket은 어떻게 함께 이해해야 하는가?
- 손실, 중복과 순서 변경을 애플리케이션이 어떻게 바라봐야 하는가?
- 데이터그램이 버퍼보다 클 때 어떤 일이 생기는가?
- 송신 성공은 상대방 수신을 보장하는가?
